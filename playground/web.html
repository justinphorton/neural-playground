Neural playground

Send signals into a fixed, untrained network of neurons and watch a simple linear readout turn its response into an answer, one step at a time.

iThe big picture

Zap a dish of neurons, record how they react, and train only a simple readout to turn that reaction into an answer.

More detail

A dish of neurons sits on a grid of metal pads called electrodes. Each electrode can zap (make nearby neurons fire) or listen (record their spikes). We write an input in with zaps, let the network react, read the reaction out, and train only a simple model at the end. That's reservoir computing.

youtask input→ fixedbits → zaps→ fixed300 neurons→ fixedspikes → numbers→ trainedlinear regression→ resultanswer

Only the linear regression is trained (once, on 100 example trials). The neurons and the zap/decode rules never change, and nothing learns while you play.

Press Send, then use the playback bar to scrub through the trial. Cards follow the signal in order.

Things to try

  • Load each task input and compare the bursts in the activity chart and raster. Whatever differs between inputs is what the readout can use.
  • Move a pulse a few ms earlier or later, then compare the original and your version with Run ×10 (step 8). Timing changes how pulses interact in the network.
  • Weaken a pulse to 15–20 µA (little or no burst: too weak to make neurons fire) or strengthen it past 100 µA (a bigger burst that reaches more electrodes). Strengths far outside what the readout trained on give less reliable answers.
  • Move a pulse to another electrode. Different neurons respond first, and the weights were tuned to the original electrode's response, so the answer becomes close to arbitrary.
  • Send nothing (Clear, then Send). Only background noise: a few random spikes and no bursts.
  • For any change: check step 5 for tall bars in quiet windows, which mean noise swung the answer.

3The reservoir's output: a fingerprint of 1,536 numbers fixed rule

Linear regression can't read "spike events", it needs the same list of numbers every trial. So for each of the 128 electrodes we count the spikes it heard in each 5 ms window (0–5, 5–10, … 55–60 ms): 128 × 12 = 1536 numbers. This table is where and when the network was active. It says nothing about bits, and it's the only thing the next step ever sees.

spikes→count per electrode, per 5 ms→128 × 12 table→ flatten: one list of 1536 numbers→into linear regression (step 4)
Send a pattern to see its fingerprint.

4How linear regression acts on the fingerprint weights trained once

Linear regression has one weight per number: how much one spike at that electrode, in that 5 ms window, pushes the answer toward 1 (teal) or 0 (red). Each count × its weight = a vote. Add up every vote plus a start value and you get the score. The weights were learned once from 100 example trials and never change.

How were the weights learned?

1 · Collect examples. We ran 100 trials: an equal number of each task input, each with fresh background noise. For every trial we kept two things: its fingerprint (the 1536 spike counts from step 3) and its right answer. The neurons were just doing their thing; nothing about them was adjusted.

2 · Fit the weights. Linear regression looked for one weight per count, plus a start value, so that for every one of those 100 trials start + Σ weight × count comes out as close as possible to that trial's right answer. "Close" means the smallest total squared miss (ordinary least squares). There are no rounds or epochs: it's solved in one go, in milliseconds, then frozen.

3 · What the windows ended up meaning. The windows right after the pulses carry the network's response, so that's where the useful weights should be. Which windows matter, and in which direction, depends on this task's encoding.

4 · Why the grid looks speckled. Windows with no pulses nearby only ever contain random background spikes, so ideally their weights would be about 0. But with 1536 weights and only 100 examples, least squares can also tune weights to fit the particular noise in those 100 trials. That's the scattered red and teal in quiet windows: memorized noise. It's harmless on the training trials but swings the score on new ones (see step 8).

5Why it gave that answer: the votes, added up trained weights

Step 4's votes, summed per 5 ms window, left to right. Tall bars decided the answer. Bars right after your pulses mean it used the real response; a tall bar in a quiet window means a stray noise spike swung it.

More detail

Score = start + w₁·f₁ + … + w₁₅₃₆·f₁₅₃₆; each bar here is all the votes from one time window (one column of step 4's vote grid). With more weights than training trials, plain linear regression over-trusts rare noise. Ridge regression fixes that (see README).

7Without neurons: a line on the raw inputs best: –

The same kind of model fed just the raw inputs. The best any straight line can do is the bar the neurons have to clear.

More detail

Linear regression on the raw inputs is w₁·x₁ + w₂·x₂ + … + start: one straight cut through the inputs. If the right answers can be separated that way, it already solves the task without any neurons; if not, no choice of weights can.

8Is the answer reliable? Run it 10 times

One click is one noisy sample. Run the same pulses 10 times to see how spread out the answers are. To check if a change mattered (e.g. a pulse 1 ms later), run the original ×10, then your change ×10: if the two rows of dots overlap, your change did no more than the background noise does.

Each dot is one trial's score; the latest 3 runs stay stacked so you can compare them.
